Capabilities

Built for accuracy, not speed

Every architectural decision in Nutri-RAG prioritises verifiable, grounded answers over fast but unreliable generation.

Textbook-Grounded Retrieval

The knowledge base is limited to peer-reviewed nutrition and medical textbooks. No web scraping, no unverified sources — every answer traces back to indexed textbook chunks.

LangGraph Agent Routing

Queries are classified before retrieval. Greetings are answered directly; off-topic queries are politely rejected; nutrition queries go through the full RAG pipeline.

Context Proof & Citations

Each response includes a grounding proof — retrieved chunk count, top cosine similarity score, and clickable source pills that show the exact textbook passage used.

Dual LLM Backend

Runs gemma3:1b locally via Ollama for development, with automatic failover to llama-3.3-70b-versatile on Groq for production-grade quality.

pgvector Similarity Search

Embeddings live in Supabase PostgreSQL via the pgvector extension. Cosine similarity retrieves the top-k most relevant textbook passages per query.

Session Export

Research sessions persist in-browser and can be exported as formatted Markdown transcripts — complete with all citations, similarity scores, and context proofs.

System Design

How a query becomes an answer

The LangGraph pipeline routes, embeds, retrieves, and synthesises in four deterministic steps — no shortcuts, no hallucination.

1

Intent Classification

The LangGraph agent classifies the query into NUTRITION, GREETING, or OFFTOPIC. Only nutrition queries proceed to retrieval — others are handled or politely rejected immediately, keeping the system focused.

LangGraph llama-3.3-70b / gemma3:1b
2

Query Embedding

The query text is vectorised locally using E5-base-v2 (768 dimensions, f16 precision via Ollama). The resulting embedding is L2-normalised for cosine similarity comparison against the indexed chunks.

jeffh/intfloat-e5-base-v2:f16 768 dims Ollama
3

Vector Retrieval (pgvector)

The embedding is matched against the textbook chunk store in Supabase PostgreSQL via cosine similarity. Top-k relevant passages and their scores are returned. If no chunks pass the similarity threshold, a fallback message is returned — no hallucination allowed.

Supabase pgvector cosine similarity
4

Grounded Answer Synthesis

Retrieved chunks are injected into a structured prompt. The LLM generates a response strictly from the provided context, annotated with a context proof (chunk count, top similarity score) and clickable source citations.

FastAPI Groq API context proof Prometheus metrics
